# Finite MPFR, Single-Draft First-Arrival, and Finite Multi-Draft PFR

This note explains the implementation of:

- `accuwm/finite_multi_draft_pfr.py`
- `accuwm/pfr_mpfr_firstarrival.py`

The most important shared primitive is finite MPFR:

```python
finite_mpfr_tokens_from_logprobs(
    target_logprobs,
    proposal_logprobs,
    source,
    num_samples,
    ...
)
```

It implements the finite proposal version of mapped Poisson functional representation
for a discrete vocabulary.

## 1. MPFR Variable Mapping

The finite MPFR algorithm samples candidate proposals from a public proposal
distribution and reweights their Poisson arrival times so that the returned
tokens have the target distribution.

In code:

```python
target_logprobs   # log P(z): distribution we want to sample from
proposal_logprobs # log Q(z): distribution used to propose candidates
source            # keyed shared random source for this context
num_samples       # B: number of MPFR samples to return
```

The mathematical quantities are:

```text
r(z)       = P(z) / Q(z)
w_lower    = inf_z Q(z) / P(z) over P-positive support
t_i        = cumulative Poisson arrival time
Z_i        ~ Q
S_i        = t_i / r(Z_i) = t_i * Q(Z_i) / P(Z_i)
```

The algorithm keeps the `B` smallest scores `S_i`. It can stop once the current
worst kept score is no larger than the best possible score any future proposal
could achieve:

```text
max_kept_score <= t * w_lower
```

where `t` is the current cumulative Poisson time.

## 2. Core MPFR Implementation

The core implementation is `finite_mpfr_tokens_from_logprobs` in
`finite_multi_draft_pfr.py`.

### 2.1 Input normalization and support check

Code:

```python
target_logprobs = _as_1d_logprobs(target_logprobs, "target_logprobs")
proposal_logprobs = _as_1d_logprobs(proposal_logprobs, "proposal_logprobs")

ratio, w_lower_value = _support_checked_ratio_and_bound(
    target_logprobs,
    proposal_logprobs,
    w_lower,
)
```

This corresponds to:

```text
r(z) = P(z) / Q(z)
w_lower = inf_z Q(z) / P(z)
```

`_support_checked_ratio_and_bound` checks absolute continuity:

```text
P(z) > 0 implies Q(z) > 0
```

If the caller does not provide `w_lower`, the code computes the exact finite-vocab
minimum:

```python
log_inv_ratio = proposal_logprobs[active] - target_logprobs[active]
w_lower_value = math.exp(float(log_inv_ratio.min().item()))
```

For a discrete vocabulary this is already the exact optimizer over support; no
continuous optimizer is needed.

### 2.2 Proposal CDF

Code:

```python
proposal_probs = proposal_logprobs.exp()
proposal_probs = proposal_probs / proposal_probs.sum()
proposal_cdf = torch.cumsum(proposal_probs, dim=0)
proposal_cdf[-1] = 1.0
```

This builds the inverse-CDF sampler for:

```text
Z_i ~ Q
```

Candidate tokens are later generated by:

```python
tokens = torch.searchsorted(proposal_cdf, uniforms[:, 1].contiguous(), right=False)
```

### 2.3 Keyed shared random source

Code:

```python
numpy_rng = source.numpy_rng()

def draw_uniforms(count: int) -> FloatTensor:
    uniforms_np = numpy_rng.random((count, 2)).astype("float32")
    return torch.from_numpy(uniforms_np).to(device=device)
```

Each proposal consumes two uniforms:

```text
uniforms[:, 0] -> exponential interarrival E_i = -log U_i
uniforms[:, 1] -> proposal token Z_i via proposal CDF
```

The same `SharedPFRSource` label and key reconstruct the same random stream for
draft-side and target-side MPFR calls at the same context.

### 2.4 Fast path for P equals Q and B equals 1

Code:

```python
same_distribution = bool(torch.equal(target_logprobs, proposal_logprobs))

if num_samples == 1 and same_distribution:
    uniforms = draw_uniforms(1)
    exp_interarrival = -_safe_log(uniforms[:, 0])
    token = torch.searchsorted(proposal_cdf, uniforms[:, 1].contiguous(), right=False).long()
    ...
```

If `target_logprobs == proposal_logprobs`, then:

```text
r(z) = P(z) / Q(z) = 1
S_i = t_i
```

Since Poisson arrival times are strictly increasing, the first proposal is exactly
the MPFR winner. The returned token is still random:

```text
Z_1 ~ Q
```

This is an exact shortcut, not an approximation.

### 2.5 Chunked vectorized top-B loop

Code:

```python
while used < max_proposals:
    take = min(chunk_size, max_proposals - used)
    uniforms = draw_uniforms(take)
    exp_interarrivals = -_safe_log(uniforms[:, 0])
    times = float(t) + torch.cumsum(exp_interarrivals, dim=0)
    tokens = torch.searchsorted(proposal_cdf, uniforms[:, 1].contiguous(), right=False).long()
    token_ratio = ratio[tokens]
    scores = torch.where(
        token_ratio > 0,
        times / token_ratio,
        torch.full_like(times, float("inf")),
    )
```

This is the vectorized version of the scalar loop:

```text
t += Exp(1)
Z_i ~ Q
S_i = t / r(Z_i)
```

The best `B` scores are maintained by concatenating the current kept candidates
with the current chunk and applying `torch.topk`:

```python
keep = min(num_samples, combined_scores.numel())
best_scores, best_pos = torch.topk(
    combined_scores,
    k=keep,
    largest=False,
    sorted=True,
)
best_indices = combined_indices[best_pos]
best_tokens = combined_tokens[best_pos]
```

The stopping check is:

```python
if best_scores.numel() >= num_samples and float(best_scores[-1].item()) <= t * w_lower_value:
    terminated = True
    break
```

This is the finite MPFR stopping condition:

```text
B-th smallest score <= current time * inf_z Q(z) / P(z)
```

The implementation checks the condition once per chunk. That can over-generate
some proposals inside the final chunk, but it does not change the returned top-B
tokens: after the stopping condition is true, future proposals cannot beat the
current kept set.

### 2.6 Failure and incomplete mode

If the stopping condition is not reached within `max_proposals`, the default is:

```python
raise RuntimeError(...)
```

If `allow_incomplete=True`, the function returns the best candidates seen so far
and marks:

```python
terminated=False
```

This is useful for timing experiments, but it is no longer exact finite MPFR.

### 2.7 Uniform proposal helper

`finite_mpfr_tokens_from_uniform_proposal` wraps the general MPFR primitive with
a fixed uniform proposal over the vocabulary:

```python
proposal_logprobs = torch.full(
    target_probs.shape,
    -math.log(target_probs.shape[-1]),
    ...
)
```

It also sets:

```python
w_lower = 1 / (V * max_z P(z))
```

because for uniform `Q(z)=1/V`:

```text
inf_z Q(z)/P(z) = min_z 1/(V P(z)) = 1/(V max_z P(z))
```

## 3. `pfr_mpfr_firstarrival.py`: Single-Draft Speculative PFR with MPFR

This file implements a single-draft speculative decoder where the original PFR
winner primitive is replaced by:

```text
MPFR(distribution, proposal, source, 1)
```

The main public entry point is:

```python
pfr_mpfr_firstarrival_sample_generator(...)
```

### 3.1 Proposal choices

`mpfr_first_arrival_from_logits` converts model logits to a target distribution:

```python
logprobs = F.log_softmax(logits, dim=-1)
```

Then it selects the MPFR proposal distribution:

```python
if proposal == "uniform":
    proposal_logprobs = uniform_proposal_logprobs(...)
elif proposal == "draft_model":
    proposal_logprobs = flat_logprobs
elif proposal == "gaussian":
    proposal_logprobs = gaussian_proposal_logprobs(...)
```

Meaning:

- `uniform`: MPFR proposes tokens uniformly over the vocabulary.
- `draft_model`: MPFR proposal is the current model distribution.
- `gaussian`: MPFR proposal is a fixed discrete Gaussian over token ids.

If `proposal_logprobs` is passed explicitly, it overrides the named proposal.
This is used on the target side when the proposal should be the draft model's
distribution for the same context.

### 3.2 Draft phase

`draft_mpfr_firstarrival_block` repeatedly runs the draft model for up to
`lookahead` tokens.

For each draft context:

```python
label_info = labeler.label_info(running_ids)
source = source_factory.build(label_info.source_label)
new_token, logprobs, mpfr_result = mpfr_first_arrival_from_logits(
    logits,
    source,
    model.device,
    proposal=proposal,
    ...
)
```

This does:

```text
draft token = MPFR(Q(. | context), proposal, source, 1)
```

The draft block stores:

```python
draft_tokens
draft_logprobs
draft_mpfr_results
labels
sources
```

The stored `sources` are critical. They are reused by the target side so that
draft and target MPFR calls at the same realized context use the same keyed
Poisson stream.

When `proposal="draft_model"`, the draft-side call is:

```text
MPFR(Q, Q, source, 1)
```

This exactly returns the first proposal `Z_1 ~ Q`. It is still sampling from the
draft model; it simply stops after one proposal because `P=Q` inside MPFR.

The draft phase also computes `bonus_logprobs` for the next draft context when
needed. This is used if the target accepts the full speculative block and needs
a bonus target token with `proposal="draft_model"`.

### 3.3 Verify phase

`verify_mpfr_firstarrival_block` evaluates the target model on the draft path:

```python
output = model(input_tokens, past_key_values=past_key_values)
logits = output.logits[:, -draft_len - 1 :, :]
target_logprobs = F.log_softmax(logits, dim=-1)
```

For each drafted position `s`, it reuses the draft context's source:

```python
source = draft_block.sources[s]
winner, _, mpfr_result = mpfr_first_arrival_from_logits(
    logits[:, s, :],
    source,
    model.device,
    proposal_logprobs=(
        proposal_logprobs[0, s, :] if proposal_logprobs is not None else None
    ),
    proposal=proposal,
    ...
)
```

This corresponds to:

```text
target winner = MPFR(P(. | context), proposal, same_source, 1)
```

Acceptance is token equality:

```python
if winner_id != draft_token:
    accepted_tokens.append(winner_id)
    accepted_count = s
    break
```

If all draft tokens are accepted, a bonus token is sampled at the final realized
context:

```python
bonus_winner, _, bonus_mpfr_result = mpfr_first_arrival_from_logits(...)
accepted_tokens.append(int(bonus_winner.item()))
```

### 3.4 Generator loop and cache update

`pfr_mpfr_firstarrival_generator` alternates:

1. Draft block generation by the reference model.
2. Target verification.
3. Label commit.
4. KV-cache update.
5. Yield output ids, output logprobs, and diagnostic metadata.

The yielded metadata includes MPFR diagnostics:

```python
{
    "accepted_count": verify_block.accepted_count,
    "draft_len": draft_block.draft_tokens.shape[1],
    "draft_mpfr": [...],
    "verify_mpfr": [...],
    "bonus_mpfr": ...,
}
```

Each MPFR diagnostic record contains:

```python
{
    "num_proposals": result.num_proposals,
    "w_lower": result.w_lower,
    "terminated": result.terminated,
}
```

This is useful for diagnosing whether low token rate comes from long MPFR
stopping times or from model forward/cache behavior.

## 4. `finite_multi_draft_pfr.py`: Finite Multi-Draft PFR

This file applies the same finite MPFR primitive to a tree-structured multi-draft
speculative sampler.

The public entry point is:

```python
finite_multi_draft_pfr_sample_generator(...)
```

### 4.1 Draft tree construction

`build_finite_multi_draft_tree` starts from the root context and expands the
tree up to `lookahead` depth.

At each occupied context, it runs the draft model:

```python
output = ref_model(...)
logits = output.logits[:, -1, :]
logprobs = F.log_softmax(logits, dim=-1)
```

Then it samples as many draft proposals as the context multiplicity:

```python
draft_tokens = finite_mpfr_tokens_from_uniform_proposal(
    logprobs[row],
    source=source,
    num_samples=multiplicities[context],
    ...
)
```

This corresponds to:

```text
draft proposals at context c:
MPFR(Q(. | c), uniform, source(c), multiplicity(c))
```

Equal tokens are merged into child contexts:

```python
token_counts[int(token)] = token_counts.get(int(token), 0) + 1
draft_sets[context] = set(token_counts)

for token, count in token_counts.items():
    child = context + (token,)
    multiplicities[child] = count
```

So the tree stores distinct draft tokens, while multiplicity tracks how many
homogeneous draft branches reached each child.

### 4.2 Target evaluation

`evaluate_finite_target_context` samples the target-side MPFR winner for a
specific context:

```python
tokens = finite_mpfr_tokens_from_uniform_proposal(
    logprobs[0],
    source=source,
    num_samples=1,
    ...
)
```

This corresponds to:

```text
target token at context c:
MPFR(P(. | c), uniform, source(c), 1)
```

The same `context_cache.source(context)` is used for draft and target when the
context key is the same, so the Poisson source is shared.

### 4.3 Block-level accept/reject

`finite_multi_draft_pfr_block` first builds the draft tree, then follows the
realized target path:

```python
current = root
for _ in range(block_len):
    token, logprobs, source, target_context_past = evaluate_finite_target_context(...)
    output_tokens.append(token)

    token_was_drafted = token in draft_sets.get(current, set())
    if not token_was_drafted:
        accepted = False
        break

    accepted_count += 1
    current = current + (token,)
```

This implements the multi-draft acceptance rule:

```text
Accept the target token at context c if it appears among the distinct draft
tokens generated at c. Otherwise emit the target token and end the block.
```

If every target token through the lookahead depth is accepted, the implementation
emits one bonus target token:

```python
if accepted and not got_eos and len(output_tokens) < max_new_tokens:
    token, logprobs, bonus_source, target_past_for_next = evaluate_finite_target_context(...)
    output_tokens.append(token)
```

### 4.4 Generator metadata

`finite_multi_draft_pfr_generator` yields either:

```python
(output_ids, output_logprobs)
```

or, with `return_meta=True`:

```python
(output_ids, output_logprobs, meta)
```

where:

```python
meta = {
    "accepted_count": block.accepted_count,
    "draft_tree_size": block.draft_tree_size,
    "target_context_count": block.target_context_count,
    "draft_len": min(lookahead, max_length - generated),
    "num_drafts": num_drafts,
}
```

`draft_tree_size` counts how many draft contexts owned keyed sources during tree
construction. `target_context_count` counts target-side contexts evaluated in
the realized path, including the bonus context when applicable.

## 5. Important Implementation Details

### Shared source is context keyed

Both files rely on:

```python
PFRSourceFactory(private_key).build(label)
```

For the same context label and secret key, draft and target use the same
`SharedPFRSource`. This is what makes the sampling watermarkable and gives the
accept/reject event shared randomness.

### MPFR proposal is internal to MPFR

The MPFR `proposal_logprobs` is not necessarily the speculative draft model.
It is the proposal distribution inside the finite MPFR primitive.

Examples:

```text
finite_multi_draft_pfr.py:
    draft side  = MPFR(Q_model, uniform, source, B)
    target side = MPFR(P_model, uniform, source, 1)

pfr_mpfr_firstarrival.py with proposal="draft_model":
    draft side  = MPFR(Q_model, Q_model, source, 1)
    target side = MPFR(P_model, Q_model, source, 1)

pfr_mpfr_firstarrival.py with proposal="uniform":
    draft side  = MPFR(Q_model, uniform, source, 1)
    target side = MPFR(P_model, uniform, source, 1)
```

### `MPFR(Q, Q, 1)` returns the first proposal exactly

When target and proposal distributions inside MPFR are equal:

```text
r(z) = Q(z)/Q(z) = 1
S_i = t_i
```

Therefore the first Poisson arrival is the exact winner. The token is still a
random sample from `Q`; the algorithm simply does not need later proposals.

### Chunking is a performance optimization

The MPFR implementation draws proposals in chunks and maintains top-B candidates
with tensor operations. This reduces Python overhead compared with a scalar
proposal loop. It does not change the returned candidates when the exact stopping
condition is reached.

### Random source remains NumPy based

`draw_uniforms` uses `source.numpy_rng()` and copies each chunk to the target
device. This keeps the keyed random stream consistent with the rest of the
repository's PFR source convention and previous experiments.

### `allow_incomplete=True` changes exactness

When `allow_incomplete=False`, failure to satisfy the stopping condition within
`max_proposals` raises an error. When `allow_incomplete=True`, the current best
candidate set is returned even if the stopping certificate was not reached.
This is useful for experiments but is not exact finite MPFR.
